# Context Standard

Context 保存可复用事实和约定，回答“Agent 完成任务前需要知道什么”。它不描述执行步骤，也不保存原始聊天。

## Context 类型

| 类型 | 示例 | 建议复核周期 |
| --- | --- | --- |
| 组织 | 身份、使命、团队和长期原则 | 每季度 |
| 转型 | Charter、当前 Initiative 组合 | 每月或阶段变化时 |
| 品牌与产品 | 受众、口径、产品事实 | 每月 |
| 领域 | 部门约束、已确认业务规则 | 每月或流程变化时 |
| 证据摘要 | 微信或其他来源的结构化输入 | 一个月内完成确认或归档 |

## 应进入 Context

- 团队目标、角色和经确认的责任；
- 品牌口径、受众、产品和渠道约束；
- 有来源的活动、合作和业务事实；
- 历史结果与可复用数据；
- 对多个任务都成立的政策和领域知识。

## 不应进入 Context

- Secrets、cookies、账号密码、私钥；
- 未脱敏个人信息、客户原始数据和聊天全文；
- 临时任务、截止时间、运行日志或 Agent 思考过程；
- 某次任务的执行步骤；
- 没有来源的推测；
- 大型二进制素材。

## 写作和升级

使用 `_template/context-record.md`，区分已确认事实、观察、约束、未知问题、证据和影响。新增文件后登记到 `brain/catalog.json`。

从微信、访谈或其他资料提取的内容先建立 Draft Evidence Summary。只有对应 Domain Owner 确认后，才能写入或升级 Active Context。方向、权限和责任变化还必须创建 Decision。

如果飞书、腾讯文档、AWS、微信和 GitHub 同时存在同一事实，Context 必须声明权威来源。GitHub 文件是 Agent 可读快照，不自动取代业务系统的 source of truth。
