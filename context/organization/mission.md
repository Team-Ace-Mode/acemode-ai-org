# AI Native Organization Mission

## Desired Outcome

把 AceMode 从主要依赖人工协调和传统职能分工的团队，逐步改造成由可靠 Context、Agent、Skill、Workflow、Human Gate 和 Eval 共同支撑的组织。Agent 负责可重复、可验证的执行，人负责目标、真实体验、监督、反馈、风险决策和最终验收。

## Verified Principles

- 组织优化的对象是工作方式和责任结构，不只是给个人增加 AI 工具。
- 尽量让 Agent 承担重复、机械和可验证的工作；团队明确表达了“宁愿烧 Token 也不烧人的时间”。
- 新流程先与原人工流程并行验证，证据充分后再逐步替换。
- 强依赖真实体验、专业判断或外部责任的工作必须保留实质性人工参与。
- 团队知识应进入 Agent 可访问、可追溯、可更新的 Context Pool。
- 工具可用不代表动作已获授权；责任和权限必须单独定义。

## Current Strategic Focus

第一阶段建设组织级 Brain 和治理框架，并以自媒体运营作为首个部门 Pilot，验证知识进入、能力建设、人机交接、验收和复盘的完整闭环。

## Constraints

- AI Native 不等于无人负责；每项正式能力必须有 Owner 和 Approver。
- 自动化不能绕过真实性、隐私、权限、品牌和发布审核。
- 不因单次演示成功就把能力升级为 Active。
- 顶层框架保持跨部门通用，具体业务方法放在对应 Context、Skill 和 Workflow 中。

## Open Questions

- 各部门正式 Owner、Approver 和 Skill Maintainer 名单。
- GitHub、微信、腾讯文档、飞书和 AWS 的长期 source-of-truth 分工。
- 第一阶段节省时间、质量、返工和采用率的基线数据。
