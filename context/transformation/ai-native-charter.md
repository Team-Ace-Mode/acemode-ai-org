# AI Native Transformation Charter

## Mandate

AI Transformation Lead 负责建立一套跨部门通用的组织框架，让团队可以持续发现适合 Agent 的工作、把隐性知识变成受治理资产、验证人机协作方式，并依据证据决定扩大、修改或停止。

## Transformation Unit

转型的基本单位是“业务能力”，不是某个模型、工具或单次自动化。一个业务能力只有同时具备以下部分，才有资格进入正式运行：

1. 已核验 Context；
2. 明确 Owner 与 Approver；
3. 可复用 Skill 或确定性 Tool；
4. 描述触发和交接的 Workflow；
5. 不可委托责任对应的 Human Gate；
6. 可复现的 Eval 和真实运行证据。

## Organization Loop

```text
方向与约束
  → 真实业务证据
  → Initiative / Pilot
  → Context、Skill、Workflow、Tool、Gate、Eval
  → 受控运行
  → 指标与人工反馈
  → 升级、修改、暂停或归档
  → 组织知识更新
```

## Stage Strategy

- 先建立 GitHub 控制面和治理合同。
- 从一个低风险、可完整审核的部门 Pilot 开始。
- 与现有人工流程并行，采集质量、时间和返工证据。
- 只有证明价值且责任清楚的能力才扩大使用。
- 云端无人值守运行必须晚于本地/有人参与的 Pilot。

## Non-goals for the Current Stage

- 不立即重组或取消传统部门。
- 不把所有聊天和文档搬进 GitHub。
- 不预先为每个部门设计具体功能。
- 不在顶层框架中绑定模型或供应商。
- 不用自动化数量代替业务价值。
