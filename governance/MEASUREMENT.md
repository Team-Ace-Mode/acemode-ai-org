# AI Native Measurement

## 衡量原则

指标用于判断组织是否减少人的机械劳动，同时保持或提高业务质量。自动化数量、Token 消耗和工具调用次数不能单独代表价值。

## 组织 Scorecard

| 维度 | 核心指标 | 计算方式 |
| --- | --- | --- |
| 人的时间 | 每次任务人工分钟数 | Pilot 与人工基线对比 |
| 周期 | 从输入完整到交付通过的时间 | 中位数与 P90 |
| 质量 | 首次通过率、禁错项失败数 | Approver 验收记录 |
| 返工 | 人工修改分钟数、主要返工原因 | 每次运行记录 |
| 可靠性 | 成功率、停止率、恢复时间 | Workflow / Tool 日志 |
| 采用 | 实际使用人数、有效运行次数 | 按团队和周期统计 |
| 成本 | 模型、工具和基础设施成本 | 每次成功交付成本 |
| 知识健康 | Active Context 过期率、Owner 缺失数 | Catalog 校验 |
| 关键人依赖 | 无原负责人参与仍能完成的比例 | 代表性任务演练 |

## Pilot 最小基线

在首次真实运行前记录至少 5 次人工任务，或在样本不足时记录所有可获得实例：

- 总耗时与人工有效工作时间；
- 等待和沟通时间；
- 首次通过情况；
- 返工次数和原因；
- 错误及影响；
- 涉及人员；
- 当前工具成本。

## 晋级判断

Pilot → Active 必须同时满足：

- 关键禁错项为零；
- Domain Approver 确认质量可接受；
- 人工时间或交付周期有可解释改善；
- 返工没有抵消收益；
- 成本和权限在批准范围内；
- 失败可检测、可停止、可恢复；
- Owner、维护者和复核周期明确。

不要求所有指标同时大幅改善。晋级 Decision 必须说明主要收益、接受的代价和下一次复核时间。

## 评审节奏

- 每周：Leader 检查阻塞、下一 Gate 和异常。
- 每两周：Pilot Owner 检查运行证据和返工原因。
- 每月：Founder 与 Leader 检查组合价值、资源和停止事项。
- 每季度：复核 Charter、角色、权限、安全边界和 Active 能力。
